# Kronos SPX — تجربة التنبؤ داخل الجلسة + اختبار رجعي

## التثبيت (مرة واحدة)
```bash
git clone https://github.com/shiyu-coder/Kronos.git
pip install torch
pip install -r requirements.txt
```
ضع `kronos_spx.py` بجانب مجلد `Kronos` (أو مرّر `--kronos-dir`).
أول تشغيل ينزّل أوزان النموذج من Hugging Face تلقائياً (Kronos-base ≈ 400MB).

## الاستخدام
```bash
# نفس تجربة 2 أكتوبر: قطع عند 11:00 نيويورك (6:00 م الرياض)، 400 شمعة، حتى شمعة 15:55
python kronos_spx.py single --date 2026-10-02

# اختبار رجعي على كل جلسات آخر ~60 يوم
python kronos_spx.py backtest --model small --paths 10

# أصل آخر / وقت قطع آخر
python kronos_spx.py single --ticker QQQ --cutoff 10:30 --paths 50 --use-volume
```

## الخيارات المهمة
| الخيار | الافتراضي | المعنى |
|---|---|---|
| `--ticker` | `^GSPC` | رمز ياهو (SPX، `^NDX`، SPY، سهم…) |
| `--cutoff` | `11:00` | آخر لحظة يرى فيها النموذج البيانات (توقيت نيويورك) |
| `--lookback` | 400 | عدد الشموع المدخلة (الحد 512) |
| `--model` | base | mini / small / base |
| `--paths` | 30 | عدد المسارات العشوائية المستقلة |
| `--seed` | 42 | المسار رقم 0 بنفس البذرة يطابق تجربة "المسار الواحد" |
| `--csv` | — | ملف شموع 5 دقائق خاص بك |
| `--days` | 90 | أيام التاريخ من Polygon (يُستخدم تلقائياً إذا وُجد POLYGON_API_KEY، وإلا ياهو) |
| `--use-volume` | معطّل | استخدم الحجم الحقيقي (للأسهم وETF فقط؛ المؤشرات بلا حجم) |

## المخرجات (مجلد `output/`)
- **single:** لوحة PNG بنفس تصميم المنشور + نطاق 10–90% + المسار المتوسط، وملف CSV للمسارات.
- **backtest:** CSV لكل جلسة + رسم أخطاء Kronos مقابل الخط الأساسي + ملف ملخص:
  - متوسط/وسيط خطأ الإغلاق: متوسط المسارات، مسار واحد، و"السعر لا يتغير"
  - نسبة الجلسات التي تفوّق فيها Kronos على الخط الأساسي
  - دقة الاتجاه (الكل، وحين تكون الثقة ≥65%)
  - تغطية النطاق (المثالي ≈ 80%) — يكشف إن كان النموذج واثقاً أكثر من اللازم

## ملاحظات
- يعمل على CPU؛ base مع 30 مساراً يأخذ دقائق للجلسة الواحدة. للاختبار الرجعي ابدأ بـ `--model small --paths 10`.
- ياهو يحتفظ بـ 60 يوماً فقط من شموع 5 دقائق؛ لفترة أطول استخدم `--csv`.
- المعيار الحقيقي ليس خطأ يوم واحد، بل: هل يتفوق على "السعر لا يتغير" عبر عشرات الجلسات؟

## التشغيل على GitHub Actions
الملف `.github/workflows/kronos.yml` في جذر المستودع:
- **يدوياً:** تبويب Actions ← Kronos SPX Forecast ← Run workflow (تختار الوضع والتاريخ والرمز).
- **تلقائياً:** كل يوم تداول بعد الإغلاق (12:15 ص بتوقيت الرياض) على آخر جلسة.
- النتائج في `kronos/results/`، وكملف قابل للتنزيل في صفحة التشغيل.
- تيليجرام: يستخدم نفس أسرار الماسحات (`TG_TOKEN` و`TG_CHAT`).
